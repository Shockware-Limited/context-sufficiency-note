\begin{abstract}
Context retrieval for a language model that edits code is evaluated almost entirely by end-task pass rate. There is no agreed definition of what context is \emph{sufficient}, and the natural baselines, program slicing and the principle of total evidence, assume a reader for whom more information never hurts. Language models are not such readers: their accuracy falls as input grows. This note fixes definitions that take that into account. A change request is a contract $(\Delta, D, I)$ with an explicit frame condition and an oracle $V_C$ that approximates it. A context $K$ is \emph{$\eps$-sufficient} for an editor $A$ when $A$'s success on $K$ is within $\eps$ of its success on the best context in a stated candidate family, not on the full repository. Under a stylised coverage-times-degradation model we prove, and mechanise in Lean~4, that $\eps$-sufficiency is not closed under superset, with a drop that grows with the amount of irrelevant material, while it is closed under superset for a lossless reader. We state the forward slice as a requirement on the oracle, give three design properties that would make the minimal context computable, and report a mutation-based measurement on a real Go repository of how often a body-only change is caught only by tests outside the changed package, together with the token cost of including them. Finally we describe a planned benchmark, SuffBench, whose instances carry observation-based oracle slices. No language-model experiments are reported.
\end{abstract}

\section{Problem}

A code change is produced by an editor from a request and some portion of the repository. For a compiler, or for a Bayes-rational reader, the portion can be large without penalty: by the principle of total evidence, more information never lowers expected decision quality~\cite{good1967total,blackwell1953equivalent}. Program slicing~\cite{weiser1984,horwitz1990} inherits that assumption and asks only whether a portion contains enough, computing sound over-approximations of the statements that can affect a criterion.

A language model is a different reader. It reads under a window, and its accuracy degrades with input length and with irrelevant content~\cite{liu2024lost,levy2024same,hsieh2024ruler,shi2023distracted}. Retrieval-augmented generation shows the same shape: more retrieved passages can lower accuracy~\cite{jin2024longcontext,yoran2023robust}, and the direction of the effect is not even uniform~\cite{cuconasu2024noise}. For such a reader the question is not whether a portion contains enough but whether it contains enough and not too much, and the two cannot be separated.

The term \emph{sufficient context} has been used for retrieval-augmented generation by Joren et al.~\cite{joren2024sufficient}, where it denotes an information-content property of the context alone: does the context contain what is needed to answer. The notion here is different in two respects, and we use the prefix $\eps$ to mark the difference. It is relative to the reader, since the same context can be sufficient for one editor and not another, and it is relative to the best achievable context under an external correctness oracle, not to the answer. Section~\ref{sec:related} places both against the statistical and explainability literature on approximate and minimal sufficiency.

The gap this note addresses, stated narrowly: no prior definition of minimal context for code edits combines an external correctness oracle with a frame condition, comparison to the best achievable context, and a reader whose success is non-monotone in context size.

\section{Setting}

A codebase is a graph $G=(U,E)$. $U$ is a finite set of \emph{units}, such as files, functions, or packages. $E$ is a set of typed edges, such as calls, imports, data flow, and tests-cover. A program $P$ assigns a body to each unit. Its observable behaviour is a map $\sem{P} : X \to Y$ from inputs to outputs or traces. $\Phi$ is a set of predicates over programs, including tests, type judgements, and stated invariants.

A \emph{context} is a subset $K \subseteq U$. A reader sees a sequence, not a set, so we fix a canonical serialisation $\sigma(K)$ and write $\mathrm{load}(K)$ for its length in tokens. Load is monotone under inclusion. A bounded reader has a window $L$; any model of its success should satisfy $g(\ell) = 0$ for $\ell > L$, and we will not need more than that.

\section{The contract and its oracle}

\begin{definition}[Contract]
A change request is a tuple $C = (\Delta, D, I, W)$ with $\Delta \subseteq \Phi$ the requested behaviour, $D \subseteq X$ the scope of inputs on which behaviour may differ, $I \subseteq \Phi$ the invariants, and $W \subseteq U$ a hypothesised \emph{write-set}, the units an edit is expected to change. A program $P'$ \emph{satisfies} $C$ relative to the current program $P$, written $P' \models C$, iff
\begin{align*}
\text{(a)}\quad & \forall \varphi \in \Delta.\ \varphi(P') && \text{requested behaviour}\\
\text{(b)}\quad & \forall x \notin D.\ \sem{P'}(x) = \sem{P}(x) && \text{frame: nothing else changes}\\
\text{(c)}\quad & \forall \varphi \in I.\ \varphi(P) \Rightarrow \varphi(P') && \text{invariants preserved.}
\end{align*}
\end{definition}

$C$ is \emph{well-defined} iff some $P'$ satisfies it, and \emph{precise} iff any two satisfying programs agree on $D$. Imprecision is the formal name for an ambiguous request. Condition~(b) is the frame problem of procedure specifications~\cite{borgida1995frame}; it is analogous to, not an instance of, the frame rule of separation logic~\cite{ohearn2001local}, whose footprint is heap rather than input domain. The write-set is part of the contract because everything downstream, in particular the forward slice of Section~\ref{sec:forward}, is a function of it; a localisation step that proposes $W$ is assumed to precede context selection.

Satisfaction cannot be checked directly. What is run is an \emph{oracle} $V_C \subseteq \Phi$: the tests for $\Delta$, the checks for $I$, and whatever regression tests approximate (b). We write $V_C(P') = \pass$ when every check holds. The oracle is sound for $C$ when $P' \models C$ implies $V_C(P') = \pass$, which is the usual situation, and complete when the converse holds, which it almost never is. The \emph{oracle residual} is the set $\{P' : V_C(P') = \pass\} \setminus \{P' : P' \models C\}$. Everything measured in this note is measured against $V_C$; the residual is real, unmeasured, and must be reported as such.

\section{Sufficiency for a bounded, stochastic editor}

An \emph{editor} $A$ maps a contract and a serialised context to a probability distribution over edits; an edit yields a program $A(C,K)(P)$. Fix a finite \emph{candidate family} $\Kfam \subseteq 2^U$ of contexts under consideration, which may be all of $2^U$. Write
\[
p_A(K, C) \;=\; \Pr\big[\, V_C\big(A(C,K)(P)\big) = \pass \,\big],
\qquad
p^*_{A,\Kfam}(C) \;=\; \max_{K \in \Kfam} p_A(K, C).
\]

\begin{definition}[$\eps$-sufficient context]\label{def:suff}
$K \in \Kfam$ is \emph{$(\eps, A)$-sufficient} for $C$ relative to $\Kfam$ iff $p_A(K, C) \geq p^*_{A,\Kfam}(C) - \eps$. Given a cost on contexts, by default $\mathrm{cost}(K) = \mathrm{load}(K)$, $K$ is \emph{cost-minimum} iff it is sufficient and no sufficient $K' \in \Kfam$ has strictly lower cost.
\end{definition}

Three points distinguish this from the slicing notion. The editor is a distribution, not a function, so sufficiency is a tolerance. The comparison is to the best context in the family, not to the full repository, because the full repository may itself be a poor choice. And nothing in the definition makes sufficiency closed under superset; because it is not, inclusion-minimal sufficient sets are badly behaved, which is why the definition asks for cost-minimum instead.

On $\eps$. With $\Kfam = 2^U$ the maximum is over a finite set and $\eps = 0$ is well-defined. The tolerance is needed because $p$ and $p^*$ are \emph{estimated}: each $p_A(K,C)$ from $n$ samples, and $p^*$ as a maximum over $|\Kfam|$ such estimates, so a union bound gives a statistical term of order $\sqrt{\ln(|\Kfam|/\delta)/(2n)}$ together with the usual upward bias of a selected maximum. The oracle residual is not part of $\eps$: it is a separate gap between $V_C$ and $\models C$.

\begin{assumption}[Coverage and degradation]\label{as:factor}
The editor's success factors as $p_A(K, C) = r(K, C)\cdot g_A(\mathrm{load}(K))$, where $r(K,C) \in [0,1]$ is a \emph{coverage} term depending on which units are present, and $g_A : \mathbb{N} \to [0,1]$ is the reader's \emph{degradation curve}, a non-increasing function of load. A set $S$ is \emph{irrelevant} to $K$ when $r(K \cup S, C) = r(K, C)$.
\end{assumption}

This is a stylised model and it is known to be false in its sharpest forms. Coverage is a property of the editor's needs, not of the verdict: SWE-bench-style benchmarks~\cite{xia2025agentless} withhold the fail-to-pass tests, which certainly determine the verdict, and editors still succeed. So coverage must not be read as containment of a verdict-determining slice, and the binary form $r = [O \subseteq K]$ for some fixed $O$ is only the simplest instance. Nothing in Section~\ref{sec:nonmono} depends on the shape of $r$ beyond the existence of irrelevant units.

\begin{hypothesis}[Portability of the degradation curve]\label{hyp:g}
$g_A$ can be estimated once per model from planted-fact experiments and reused across codebases.
\end{hypothesis}

This is a hypothesis, not a fact; long-context benchmarks show degradation varying with the task~\cite{hsieh2024ruler,levy2024same}. If it fails, $g_A$ must be estimated per task family, which raises the cost of applying the definitions but does not change them.

\section{Non-monotonicity}\label{sec:nonmono}

We now make Assumption~\ref{as:factor} concrete and prove that sufficiency is not closed under superset, in contrast with the lossless case. All statements in this section are mechanised in Lean~4 with Mathlib, with the optimum defined as a genuine maximum over all contexts so that the mechanised notion is exactly Definition~\ref{def:suff} with $\Kfam = 2^U$.\footnote{File \texttt{sufficiency/Sufficiency/NonMonotonic.lean}, commit \texttt{\leanCommit}, in the repository below. The development contains no \texttt{sorry}; CI audits that every theorem depends only on \texttt{propext}, \texttt{Classical.choice} and \texttt{Quot.sound}.\\ \url{https://github.com/Shockware-Limited/context-sufficiency-note}}

Fix a finite set of units $U$, a coverage function $r : 2^U \to [0,1]$ of any shape, and a degradation curve $g : \mathbb{N} \to [0,1]$. Let $p(K) = r(K)\, g(|K|)$, taking $|K|$ as the load, let $p^* = \max_{K \subseteq U} p(K)$, which is attained, and say $K$ is $\eps$-sufficient iff $p(K) \geq p^* - \eps$.

\begin{proposition}[Sufficiency is not closed under superset]\label{prop:nonmono}
Let $g$ be strictly decreasing. Let $K$ attain $p^*$, let $r(K) > 0$, and let $S \neq \emptyset$ be disjoint from $K$ and irrelevant to it. Then $p(K \cup S) < p(K)$, and for every $\eps$ with
\[
0 \;\leq\; \eps \;<\; p(K) - p(K \cup S) \;=\; r(K)\,\big(g(|K|) - g(|K|+|S|)\big),
\]
the context $K$ is $\eps$-sufficient and the context $K \cup S$ is not.
\end{proposition}
\begin{proof}
Irrelevance gives $r(K \cup S) = r(K)$, and disjointness gives $|K \cup S| = |K| + |S| > |K|$, so $p(K \cup S) = r(K)\,g(|K|+|S|) < r(K)\,g(|K|) = p(K)$ because $g$ is strictly decreasing and $r(K) > 0$. Since $p(K) = p^*$, $K$ is $\eps$-sufficient for every $\eps \geq 0$. For $K \cup S$, $p(K \cup S) < p(K) - \eps = p^* - \eps$ by the bound on $\eps$.
\end{proof}

The admissible interval for $\eps$ is non-empty and its width grows with $|S|$: the more irrelevant material is added, the larger the tolerance at which the superset still fails. This is the $k$-step form; the one-unit case $|S| = 1$ is the weakest instance, not the result. For the binary instance $r = [O \subseteq K]$ with $g$ non-increasing, the optimum is $g(|O|)$, attained at $K = O$, and the bound reads $\eps < g(|O|) - g(|O|+|S|)$. Concretely, with $g(\ell) = 1/(\ell+1)$ and $|O| = 1$, adding three irrelevant units drops success from $1/2$ to $1/5$, so every $\eps < 3/10$ separates $O$ from $O \cup S$.

\begin{lemma}[The lossless reader is closed under superset]\label{lem:lossless}
Let $g$ be constant and let $r$ be monotone under inclusion. If $K$ is $\eps$-sufficient and $K \subseteq K'$, then $K'$ is $\eps$-sufficient, for every $\eps$.
\end{lemma}
\begin{proof}
With $g \equiv c \geq 0$, $p(K') = r(K')\,c \geq r(K)\,c = p(K) \geq p^* - \eps$.
\end{proof}

The pair is the point, and it is the principle of total evidence in miniature. For a reader with constant $g$, information is free and Good's principle holds: sufficiency is monotone and minimality is a matter of removing what is unnecessary. For a reader with decreasing $g$, adding the unnecessary is a failure mode, and minimality becomes a cost-minimisation whose objective is non-monotone in the context. The mechanised statements are exactly these two, together with the fact that the optimum is attained.

\section{The forward slice as a requirement on the oracle}\label{sec:forward}

Let $W$ be the write-set. The \emph{backward slice} $B(W)$ is the set of units $W$ depends on, transitively, through the edges of $G$. The \emph{forward slice} $F(W)$ is the set of units that depend on $W$, transitively, including through test-only dependencies. Retrieval for code editors has concentrated on the backward slice and on the edit site itself~\cite{shrivastava2023repo,zhang2023repocoder,xia2025agentless,bairi2024codeplan}.

\begin{hypothesis}[Compositionality and soundness of the dependency relation]\label{hyp:comp}
The behaviour of a unit is a function of its own body and the behaviours of the units it depends on, and the dependency relation in $E$ over-approximates every channel through which one unit's behaviour can affect another's.
\end{hypothesis}

Under Hypothesis~\ref{hyp:comp}, a unit outside $W \cup F(W)$ has the same body and the same dependency behaviours before and after the edit, so its behaviour is unchanged. Every violation of condition~(b) therefore shows up in the behaviour of a unit in $W \cup F(W)$, and the checks that can observe it are the checks bound to those units. This is exactly the safety argument of regression test selection~\cite{rothermel1997safe}, which holds under the same assumption, there called the controlled regression testing assumption, and it is what change impact analysis computes~\cite{ren2004chianti}.

The hypothesis fails in practice through channels the import graph does not record: shared mutable or global state, environment and configuration, initialisation order, registration through side-effecting imports or dependency injection, build tags and generated code, reflection and serialisation, timing, and consumers outside the repository altogether. Each is a way for a frame violation to surface in a unit outside $F(W)$, or in no unit at all. Section~\ref{sec:measure} measures how often that happens in one real repository.

\begin{requirement}[Forward slice]
An oracle $V_C$ that omits the checks bound to $F(W)$ cannot observe a violation of condition~(b) that Hypothesis~\ref{hyp:comp} permits. Soundness of $V_C$ for the frame therefore requires those checks, and the units they exercise are the natural candidates for inclusion in the context.
\end{requirement}

The first sentence is a statement about the oracle and follows from the hypothesis. The last clause is an empirical claim about editors, that an editor which can see the dependents it may break will break them less often, and it is labelled as such; nothing in this note tests it.

\section{Context-closed languages}\label{sec:closed}

The quantities above are undecidable in general: whether a given unit can affect the verdict on an arbitrary program is a semantic property, and Weiser already notes that minimal slices are uncomputable~\cite{weiser1984}. They become graph queries when the language restricts programs. We state three design properties for such a restriction. They are desiderata for a core calculus that does not yet exist, not conjectures, and no language is named here. Extend $U$ with an \emph{interface node} $\mathrm{spec}(v)$ for each unit $v$, carrying its declared contract and effects, and write $\mathrm{deps}(u)$ for the units $u$ depends on.

\begin{property}[P1, interface determinacy]
If every body refines its specification, then the behaviour of $u$ is a function $F(\mathrm{body}(u), (v \mapsto \mathrm{spec}(v))_{v \in \mathrm{deps}(u)})$ of its own body and its dependencies' specifications. This is modular reasoning in the sense of Parnas~\cite{parnas1972criteria} and behavioural subtyping~\cite{liskov1994behavioral}, taken as a language guarantee rather than a discipline.
\end{property}

\begin{property}[P2, spec-bounded reliance]
If the checks bound to any unit other than $u$ depend on $u$ only through $\mathrm{spec}(u)$, and an edit leaves $\mathrm{spec}(u)$ unchanged with the new body refining it, then the verdict of every such check is unchanged. The antecedent fails whenever a dependent relies on unspecified behaviour, such as iteration order or error text; P2 is therefore a property of the language's ability to forbid that reliance, and it says nothing about condition~(b) within the latitude the specification leaves.
\end{property}

\begin{property}[P3, computable context]
For a contract with write-set $W$, let $K^*$ be the least set containing $W$, the interface nodes of $\mathrm{deps}(W)$, and, whenever an interface in $K^*$ changes, the units depending on it together with their interface nodes, closed under this rule, plus the checks bound to any unit in $K^*$. Given $G$ and syntactic equality of interfaces, $K^*$ is computable in time linear in $|G|$; constructing $G$ itself is not included in that bound.
\end{property}

\begin{definition}[Context-closed]
A language is \emph{context-closed} iff P1, P2 and P3 hold of all its programs.
\end{definition}

In a context-closed language the backward slice stops at one hop of interfaces, the forward slice is empty whenever the interface is preserved, and the undecidable question is replaced by a fixpoint over interface changes. The tolerance $\eps$ then measures only the editor's degradation. Note that $K^*$ contains interface nodes where an observation-based oracle slice would contain bodies; the two agree only if stubbing a dependency by a specification-satisfying replacement preserves the verdict, which is P1 again. Individually, the ingredients exist: declared contracts, declared effects, content-addressed definitions, acyclic modules. The property as a language guarantee is what is proposed.

\section{Measurement: how often does the forward slice matter?}\label{sec:measure}

The one claim in this note that can be tested without a language model is the one behind Requirement~1: that body-only changes are caught by tests outside the changed unit, and that those tests cost context. We measured this on the GitHub CLI repository (\texttt{cli/cli}, commit \texttt{\corpusCommit}), a single Go module of \nPkgs{} packages, taking the package as the unit, since it is Go's unit of compilation and of testing and its import graph is acyclic. Of its packages, \nTestPkgs{} have tests that pass on our platform; \nBaseFail{} fail at baseline for platform reasons and are excluded throughout. The full suite runs in about \baseSecs{} seconds.

\paragraph{Design.} We sampled packages uniformly, then a non-test file within the package, and injected exactly one mutant with a small set of body-only, signature-preserving operators: relational and arithmetic operator swaps, boolean connective swaps, condition negation, and off-by-one and string-literal perturbations. Mutants that do not compile are recorded and excluded. For each compiling mutant we ran the full suite once and recorded the set of failing test packages, then classified the mutant with $W$ the mutated package, $F(W)$ the transitive reverse dependency closure including test-only imports, and $B(W)$ the transitive dependency closure: \emph{caught by $W$} if $W$'s own tests fail; \emph{caught only outside $W$} if some test package in $F(W)$ fails and $W$'s do not; \emph{caught elsewhere} if a failing test package lies outside $W \cup F(W)$, which is a channel Hypothesis~\ref{hyp:comp} does not account for. Context sizes are measured in tokens of a public tokenizer (cl100k) over Go source, with tests counted separately. The driver, mutator, raw results and analysis script are in the repository under \texttt{experiments/}.

\paragraph{Results.} Of \nMut{} sampled mutants, \nCompile{} compiled, and \nDet{} of those were caught by the full suite. Table~\ref{tab:mut} gives the breakdown. Among caught mutants, \pctW\% were caught by the mutated package's own tests, \pctFonly\% were caught \emph{only} by tests in the forward slice, and \pctOther\% triggered a failure outside $W \cup F(W)$. Of the mutants caught only outside $W$, \pctWnoTests\% were in packages that have no tests of their own. On cost, the median mutated package is \medTokW{} tokens of source; its backward slice is \medTokB{} tokens, its forward slice \medTokF{} tokens of source plus \medTokFt{} tokens of tests, against \totTok{} tokens for the whole module. The median $K^*$-shaped context $W \cup B(W) \cup F(W)$ with tests is \medPctKstar\% of the module; \pctFitSmall\% of them fit in a 128k-token window and \pctFitLarge\% in a 200k window.

\paragraph{What this does and does not show.} The \emph{caught only outside $W$} fraction is the share of frame violations, in this proxy, that a context limited to the edit site and its backward slice cannot witness and that the forward slice can. The \emph{elsewhere} fraction is a direct, if coarse, measurement of how far Hypothesis~\ref{hyp:comp} is from holding for Go's import graph. The token columns are the cost of Requirement~1 in this repository. None of this is an editor pass rate. The numbers partly replicate what is known from regression test selection~\cite{legunsen2016extensive,gligoric2015practical}; the new part is the reading as context cost.

\paragraph{Threats.} Mutants are not real regressions, and the operator set is small. One repository, one commit, one platform, with \nBaseFail{} packages excluded for baseline failures; packages excluded as flaky could hide detections. Package granularity inflates both slices relative to a symbol-level analysis. Sampling by package, not by lines of code, weights small packages heavily. Token counts use one public tokenizer as a proxy. The transitive forward slice is an upper bound on what an editor would need to see; P3's interface-only version would be smaller.

\section{Proposed benchmark}

We reserve the name \emph{SuffBench} for a benchmark whose instances are tuples (repository snapshot, contract $C$ derived from a fail-to-pass commit including its write-set, gold patch $P'_{\text{gold}}$, oracle slice $O(C, P'_{\text{gold}})$). The oracle slice is relative to the gold patch, since different correct patches have different slices, and is computed by observation: stub each unit outside the write-set, rebuild, rerun $V_C$, and retain the unit iff the verdict changes, using delta debugging~\cite{zeller2002simplifying} to reduce the number of builds. Observation yields a 1-minimal set, which under redundancy is order-dependent; the order must be recorded. Instances must postdate the training cutoff of any evaluated model.

The dataset labels \emph{verification} relevance: what determines the verdict on the gold patch. Experiments are to measure \emph{generation} success: whether an editor given $K$ produces a passing edit. The two must not be conflated, and Assumption~\ref{as:factor} does not identify them. Any claim of the form ``less context without loss'' is to be stated as ``within $\eps$ of the best observed pass rate in family $\Kfam$ under oracle $V_C$'' with the oracle residual reported as unmeasured. Nothing is released with this note.

\section{Related work}\label{sec:related}

\emph{Sufficiency with a lossless reader.} Slicing~\cite{weiser1984,horwitz1990} and its observation-based, language-independent form~\cite{binkley2014orbs} compute sets of statements sufficient to reproduce a criterion; Weiser notes minimal slices are uncomputable, and observation-based slices are themselves not superset-closed, since restoring a single line that references a deleted declaration can break compilation. In statistics, sufficiency and its approximate form are Le Cam's~\cite{lecam1964sufficiency}; the monotonicity of information for a rational agent is Good's principle of total evidence~\cite{good1967total} and Blackwell's comparison of experiments~\cite{blackwell1953equivalent}. Lemma~\ref{lem:lossless} is that principle in the present model; Proposition~\ref{prop:nonmono} is its failure for a bounded reader.

\emph{Sufficiency relative to a model.} Explainability defines sufficient and minimal input subsets relative to a classifier's own output~\cite{deyoung2020eraser}. The present notion differs in comparing to the best context under an external oracle rather than to the model's full-input behaviour, and in the frame condition. Joren et al.~\cite{joren2024sufficient} define sufficient context for retrieval-augmented generation as a property of the context's information content; ours is reader-relative and optimum-relative.

\emph{Non-monotone retrieval.} That more context can hurt a language model is established for position~\cite{liu2024lost}, length~\cite{levy2024same,hsieh2024ruler}, irrelevant content~\cite{shi2023distracted,yoran2023robust}, and passage count~\cite{jin2024longcontext}; noise can even help~\cite{cuconasu2024noise}, which is why $g$ being non-increasing is an assumption here and not a fact.

\emph{Context for code editors and change impact.} Context is selected by learned prompt proposals~\cite{shrivastava2023repo}, iterative retrieval~\cite{zhang2023repocoder}, simple localisation~\cite{xia2025agentless}, and dependency-graph planning~\cite{bairi2024codeplan}; none states a sufficiency criterion, and all compare against task pass rate. Safe regression test selection~\cite{rothermel1997safe,gligoric2015practical,legunsen2016extensive} and change impact analysis~\cite{ren2004chianti} compute which checks a change can affect, which is the oracle half of Requirement~1. Modular reasoning through interfaces is Parnas~\cite{parnas1972criteria} and Liskov and Wing~\cite{liskov1994behavioral}; P1 to P3 ask for it as a language guarantee.

The gap, restated: no prior definition of minimal context for code edits combines an external correctness oracle with a frame condition, comparison to the best achievable context, and a reader whose success is non-monotone in context size.
